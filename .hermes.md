## ⚠️ Hard Invariant Rules for Hermes

1. **Deployment SOP**:
   - Work must be done in the local git repository on Mac, committed, and pushed to `origin main`.
   - On the VPS, pull updates via:
     `sudo -u hermes git -C /opt/data/home/sahabatmuslim-landing pull origin main`
   - Never write loose, uncommitted modifications directly on VPS web root.

2. **Database Table Naming**:
   - Table names must be **generic** (e.g. `user_sync_data`).
   - **Never** name tables with specific seasonal wording like `ramadhan`.

3. **Data Sync Strategy (Smart Merge)**:
   - When syncing user worship data between browser (`localStorage`) and PostgreSQL:
     - Always use **Smart Merge (Union)**.
     - Quran Juz completed = union set of local & cloud juz.
     - Mutabaah checklist = if marked `true` on either side, keep `true`.
     - Never blindly overwrite user data. No worship record may be lost.

4. **Mobile Navigation & Caching**:
   - Keep navbar items synchronized across all HTML pages (`index.html`, `ramadhan.html`, `quran.html`, `dzikir.html`, `doa.html`, `kiblat.html`, `kajian.html`).
   - Keep `.mobile-menu-btn * { pointer-events: none; }` intact.
   - When updating shared JS, increment the script tag version query string (`nav.js?v=X`, `ramadhan.js?v=X`) to bypass Cloudflare/browser caching.

5. **Arabic Content**:
   - Always render Arabic text using fonts (`font-family: 'Amiri', serif`). Never use images for Arabic verses/prayers.
   - Use authentic (*shahih/hasan*) hadith references.

6. **Documentation Sync**:
   - When adding features or modifying endpoints, always update `README.md`, `docs/API_AND_DATABASE.md`, and `AGENTS.md`.
